Assets

assets/ 撰写指南

纯静态资源，不含任何逻辑。作用是给 agent 提供「具体的结构可参照」——模型对具体结构 pattern-match 得比散文描述好得多。

本页内容均为建议。

1. 三类静态资源

子目录装什么用途
templates/输出模板让 agent 按固定结构产出（报告、邮件、配置）。
schemas/数据结构定义JSON Schema 等，供脚本校验、供 agent 理解字段约束。
data/静态查找表国家代码、币种、状态码映射、枚举字典。

2. 从零到成稿：四步流程

需要静态资源时，按这个顺序做。

判断类型

要固定输出结构 → 模板；要定义数据结构 → schema；要做静态映射 → 查找表。

先决定内联还是外置

小且固定的（三五个条目、短模板）直接写进 SKILL.md；长、会变、或只在特定情况用的才外置。

落盘

放对应的子目录：templates/、schemas/、data/。保持一层，文件名自解释。

在 SKILL.md 里接上路由

写明「什么情况用哪个资源」。没写触发条件的资源，等于不存在。

3. templates/ —— 输出模板

作用要固定输出格式时给模板，比用散文描述可靠——模型照着具体结构填，不易跑偏。
何时读需要按模板输出时。由 SKILL.md 路由表指明。

何时内联 vs 外置

  • 短模板 → 直接内联在 SKILL.md 里（省一次文件加载）。
  • 长模板 / 只在特定情况才用的模板 → 放 assets/templates/，按需加载。

示例：templates/report.md

# [分析标题]

## 摘要
[一段话概述关键发现]

## 关键发现
- 发现 1，附支撑数据
- 发现 2，附支撑数据

## 建议
1. 具体可执行的建议
2. 具体可执行的建议
在 SKILL.md 里怎么用："按 assets/templates/report.md 的结构输出报告，按需调整小节。"

4. schemas/ —— 数据结构定义

作用定义输入/输出的结构，供脚本校验、也供 agent 理解每个字段的类型与约束。
何时读需要构造或解析结构化数据、或校验其合法性时。

示例：schemas/field_values.schema.json

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["customer_name", "order_total"],
  "properties": {
    "customer_name": { "type": "string", "minLength": 1 },
    "order_total":   { "type": "number", "minimum": 0 },
    "signature_date":{ "type": "string", "format": "date" }
  },
  "additionalProperties": false
}
好处：脚本可拿它自动校验；agent 也能从 required 与类型约束推断"哪些字段不能缺、该填什么格式"。

5. data/ —— 静态查找表

作用存放静态映射数据，避免把大表硬编码进 SKILL.md 或脚本——既省上下文，又便于单独维护。
何时读需要做映射 / 查表时（路由表写"需要币种换算时读 assets/data/currencies.json"）。

示例：data/currencies.json

{
  "CNY": { "name": "人民币", "symbol": "¥", "decimals": 2 },
  "USD": { "name": "美元",   "symbol": "$", "decimals": 2 },
  "JPY": { "name": "日元",   "symbol": "¥", "decimals": 0 }
}
判断标准：这张表会不会变、大不大？会变或很大 → 放 data/；很小且固定（如三五个状态码）→ 直接内联在正文里更省事。

6. 组织与命名

命名小写、kebab-case；模板带明确后缀（report.md、email.md），schema 用 *.schema.json。
路径相对技能根目录，如 assets/templates/report.md。
一层保持一层子目录（templates / schemas / data）；不要再往下嵌套。
触发每个资源都要在路由表里写明"何时用"。

7. 常见错误速查

错误后果 / 纠正
把很小的固定表也塞进 assets/白加一次文件加载 → 三五个条目直接内联
模板里混入业务逻辑assets 只放静态结构，逻辑归 scripts/
资源没有触发条件永不被加载 → 在路由里写明何时用
文件 / 数据无说明至少让文件名自解释，或在路由表里说明用途
子目录继续往下嵌套保持一层（templates / schemas / data）

8. 交付前自检清单

  • 短模板、小查找表已内联在正文——没有为了它多一次文件加载
  • 每个资源都在路由表里写了何时用
  • 目录保持一层（templates / schemas / data），没有继续嵌套
  • 模板里没有混入业务逻辑（逻辑归 scripts/）
  • 文件名自解释（report.md、*.schema.json），引用用相对路径
  • 与 SKILL.md 没有内容重复
