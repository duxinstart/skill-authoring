scripts/ 撰写指南

把确定性、可重复的操作固化成脚本。脚本比让模型每次现写更可靠、更省 token，也更易测试。

本页内容除标注 硬性 的一节外，均为建议。

1. 什么时候该写脚本

  • agent 每次都在重写同一段逻辑（建图表、解析特定格式、校验输出）——这是最直接的信号。
  • 操作确定性、可重复，不该每次由模型即兴发挥。
  • 一段命令复杂到一次难以写对，不如固化成经过测试的脚本。
反例：只是调用一个带几个 flag 的现成工具（如 npx eslint@9 --fix .）——直接写在 SKILL.md 里即可，不必建脚本。

2. 从零到成稿：六步流程

决定要写脚本之后，按这个顺序做。

确认该写脚本

标准只有一条：这段逻辑 agent 每次都在重写。只是调一个现成工具，就别写脚本。

定接口

先想清楚三件事：输入怎么给（flag / 环境变量 / stdin）、输出给什么（结构化数据）、失败怎么报（退出码 + 错误信息）。

写实现

依赖内联声明并固定版本，让一条命令就能跑；不引交互式输入。

补 --help 与错误信息

--help 写清描述、全部 flag 与用法示例；错误信息要能让 agent 自己改对。

本地跑通

新写或改过的脚本必须实际运行一次——包括失败路径（缺参、错格式）。

在 SKILL.md 里接上

列出脚本清单，并在流程的对应步骤里写明什么时候跑它。路径相对技能根目录。

3. 自包含：让一条命令就能跑

脚本应自带依赖声明，agent 无需额外的 manifest 或安装步骤。

语言依赖声明方式运行
PythonPEP 723 内联 TOML（# /// script）uv run scripts/x.py（或 pipx）
Denonpm: / jsr: 导入前缀deno run scripts/x.ts
Bun导入路径内联版本（cheerio@1.0.0）bun run scripts/x.ts
Rubybundler/inline 的 gemfile doruby scripts/x.rb
Node需 package.json（非自包含）优先用上面几种
固定版本（如 "beautifulsoup4>=4.12,<5"），让命令长期行为一致。运行时依赖写进 frontmatter 的 compatibility。

4. 禁止交互式提示 硬性

agent 在非交互 shell 中运行——无法响应 TTY 提示、密码框、确认菜单。任何阻塞式等待都会永久挂起。所有输入必须通过命令行 flag、环境变量或 stdin 提供。

# 差 —— 挂起等待输入
$ python scripts/deploy.py
Target environment: _

# 好 —— 缺参时给出清晰错误与用法
$ python scripts/deploy.py
Error: --env is required. Options: development, staging, production.
Usage: python scripts/deploy.py --env staging --tag v1.2.3

5. 用 --help 交代接口

--help 是 agent 了解脚本接口的主要途径。要简短（它会进入上下文），但包含描述、全部 flag 与用法示例。

Usage: scripts/process.py [OPTIONS] INPUT_FILE

处理输入数据并生成摘要报告。

Options:
  --format FORMAT   输出格式: json, csv, table（默认 json）
  --output FILE     写入文件而非 stdout
  --verbose         将进度打印到 stderr

Examples:
  scripts/process.py data.csv
  scripts/process.py --format csv --output report.csv data.csv

6. 错误信息要能自纠

agent 拿到错误后，错误信息直接决定它的下一次尝试。含糊的一句"invalid input"等于浪费一轮。

# 差
Error: invalid input

# 好 —— 说清：错在哪、期望什么、可选什么
Error: --format must be one of: json, csv, table.
       Received: "xml"

7. 结构化输出 + stdout/stderr 分流

结构化优先 JSON / CSV / TSV，而非自由文本——既能被 agent 消费，也能接 jq / cut / awk 组成管道。
分流数据走 stdout，进度/警告走 stderr。这样 agent 能拿到干净可解析的结果，同时保留诊断信息。
# 差 —— 空格对齐，难以程序化解析
NAME          STATUS    CREATED
my-service    running   2025-01-15

# 好 —— 字段边界明确
{"name": "my-service", "status": "running", "created": "2025-01-15"}

8. 其他设计考量

幂等agent 可能重试。"不存在才创建" 比 "创建失败于重复" 更安全。
输入约束含糊输入直接报错，别猜。尽量用枚举 / 闭集。
dry-run破坏性 / 有状态操作提供 --dry-run，让 agent 先预览。
退出码不同失败类型用不同退出码，并在 --help 里说明含义。
安全默认破坏性操作要求显式确认 flag（--confirm / --force）。
控制体积工具输出常被截断（约 10–30K 字符）。大输出默认给摘要 / 限额，并提供 --offset 或要求 --output。

#!/usr/bin/env -S uv run
# /// script
# dependencies = ["pandas"]
# ///
"""从原始数据生成财务报告。一句话说明脚本做什么。"""
import argparse, sys, json

def main():
    p = argparse.ArgumentParser(description="生成财务报告")

10. 在 SKILL.md 中如何引用

先列出可用脚本，再在流程里指示运行方式；路径相对技能根目录（agent 从那里执行命令）。

## 可用脚本
- **`scripts/validate.sh`** — 校验配置文件
- **`scripts/process.py`** — 处理输入数据

## 工作流
1. 运行校验：
   ```bash
   bash scripts/validate.sh "$INPUT_FILE"
   ```
2. 处理结果：
   ```bash
   python3 scripts/process.py --input results.json
   ```
同一套相对路径约定也适用于 references/*.md 里的代码块——命令路径一律相对技能根目录。

11. 交付前自检清单

  • 脚本没有任何交互式提示——不会挂起等待输入
  • 依赖自带声明（一条命令即可运行），且版本已固定
  • 带 --help，且包含描述、全部 flag 与用法示例
  • 错误信息能自纠——说清错在哪、期望什么、有哪些可选值
  • 数据走 stdout、诊断走 stderr
  • 幂等（"不存在才创建"）
  • 破坏性操作有 --dry-run，并要求显式确认 flag
  • 大输出有限额，或提供 --offset / --output
  • 已在 SKILL.md 里列出脚本，并写明如何运行

12. 常见错误速查

错误后果 / 纠正
用了 input() / 密码提示 / 确认菜单在 agent 环境永久挂起 → 全走 flag / 环境变量 / stdin
依赖没声明跑不起来 → 内联声明依赖 + 固定版本
数据与日志混在一起输出难以解析 → 数据走 stdout，诊断走 stderr
错误信息含糊（invalid input）白费一轮 → 说清错在哪、期望什么、可选值
破坏性操作没有 --dry-run无法先预览 → 加上，并要求显式确认 flag
输出体积无上限被截断丢关键信息 → 默认给摘要 / 提供 --offset / 要求 --output
版本浮动（@latest）行为漂移 → 固定版本
写进 SKILL.md 却没在流程里指明何时跑agent 不知道何时用 → 在对应步骤里写明
