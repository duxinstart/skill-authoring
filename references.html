references/ 撰写指南

技能的按需知识库。核心思想：把「偶尔才用」的长内容从 SKILL.md 搬出来，用路由表指明何时加载。

本页内容均为建议：不做不会报错，但会明显影响效果与上下文开销。

1. 定位：什么时候才需要它

出现下面任一情况，就该建 references/：

  • SKILL.md 开始塞不下"偶尔才用"的细节，继续堆会让每次激活都白占上下文。
  • 存在只有特定情况才用得上的详细知识（领域规则、API 细节、错误表）。
  • 技能横跨多个领域，各领域知识长且互不相关。
组织原则：每个文件都应「独立、聚焦、可单独读懂」——因为它们是被整篇按需加载的，越精准越省上下文。

2. 从零到成稿：五步流程

决定要建 references/ 之后，按这个顺序做。

判断是否需要

只有当 SKILL.md 开始装不下"偶尔才用"的细节时才建。装得下就别建——多一个文件就多一次加载。

按主题拆分

一个文件一个主题。拆分依据通常是：领域（finance / legal）、条件（出错时才看）、格式（表单字段）。

命名并落盘

小写 kebab-case；优先用约定名：REFERENCE.md（主参考）、<domain>.md（领域）、FORMS.md（表单）。

写内容

每份都要独立可读、只讲一个主题。别写"如何入门"——那是 SKILL.md 的事。

在 SKILL.md 里接上路由

逐个写明「什么情况读它」。没写触发条件的参考文件，等于不存在。

3. 通用规范

一层深度所有引用只从 SKILL.md 出发一层可达；禁止 references/a/b/c.md 这类深链，也不要嵌套引用链。
命名统一小写、kebab-case；约定名优先：REFERENCE.md（主参考）、<domain>.md（领域）、FORMS.md（表单）。
必须可触发每个文件都要在 SKILL.md 路由表里写明何时加载。没写触发条件的参考文件 = 永远不会被读到。
相对路径从技能根目录算起，如 references/finance.md。
规模单文件尽量小；若某主题内容巨大，可建子目录（references/api/），但整体仍保持一层。

4. REFERENCE.md —— 主技术参考

作用技能最完整的技术说明，是 SKILL.md「简版」的详版兜底。
何时读任务需要精确细节、SKILL.md 的简版不够用时。

推荐结构

# <技能名> 技术参考

## 1. 输入 / 输出数据结构
## 2. 核心算法与公式（含口径、推导）
## 3. 参数与配置项（表格）
## 4. 完整可运行示例
## 5. 边界情况清单
## 6. 错误码与排查
别写"如何入门"——那是 SKILL.md 的职责。这里只放"精确到细节"的内容：参数表、返回值结构、边界值。

5. <domain>.md —— 领域知识

作用封装某一垂直领域的专有知识；一个领域一个文件。
何时读任务明确落在该领域时（"做财报分析" → finance.md）。
为何独立领域知识长且互不相关，合在一起会互相干扰、白占上下文。

推荐结构

# <领域>知识

## 术语表（本领域专有名词及含义）
## 口径与规则（计算 / 判定的标准）
## 合规红线（绝不能做的事）
## 常见误区（agent 容易想当然的地方）

示例：finance.md 片段

## 口径与规则
- 营收按**不含税**口径统计，除非用户明确要求含税。
- 环比 = (本期 − 上期) / 上期；上期缺失时不计算，标注"无对比"。
- 币种默认人民币；出现美元时须按报表日汇率折算，不得混加。

## 常见误区
- "毛利"指营收 − 营业成本，**不含**期间费用。
- 部分科目为负值（如退货），求和无须特殊处理，但展示时要保留符号。

6. 条件触发文档（如 api-errors.md）

作用把「只在特定条件下才需要」的知识单独成文——平时完全不加载，出问题才读。
何时读由路由表写明条件，如「当 API 返回非 200 时读取」。
价值正是条件触发——正常运行根本用不到，省下大量上下文。

8. 常见错误速查

错误后果 / 纠正
只写"详见 references/"文件永不被读 → 必须写触发条件
深层嵌套（a/b/c.md）只保留一层
一个文件塞多个不相关主题拆开，各自聚焦
把主干流程也搬进来参考文件只放细节，主干留在 SKILL.md
与 SKILL.md 内容重复既浪费上下文又易不同步 → 删掉重复
文件越长越好、什么都写按需加载是整篇读入 → 拆成多份，各自聚焦

9. 交付前自检清单

  • 每个参考文件都在 SKILL.md 里写了触发条件（"什么情况读它"）
  • 引用只一层深，没有 a/b/c.md 这类深链，也没有嵌套引用链
  • 每个文件独立可读，只讲一个主题
  • 主干流程留在 SKILL.md，没有搬进 references/
  • 与 SKILL.md 没有内容重复
  • 文件名小写、kebab-case；引用一律用相对路径
